### C2. `&` (address-of) laxness (`xc.m` `expression()`)

Current `elseif token == And` silently no-ops for any non-lvalue, diverging
from xc.c's `bad address of` error. Fix with an "is-array" flag:

- [ ] Add a global, e.g. `unit_was_array`, to the parser globals (declared in
      `xc()` and the local functions that touch it: `expression`, plus the
      unit dispatcher).
- [ ] Clear it at the start of the unit section of `expression(Inc)` parsing
      (one clear before the unit dispatch covers every unit path since
      `expression(Inc)` parses exactly one unit).
- [ ] Set it in the Id-unit array branch (`idtype >= 4096`) only.
- [ ] Rewrite the `And` branch:
      ```
      if text(ti+1) == LC || text(ti+1) == LI
          ti = ti - 1;                 % drop the load; ax = address
          expr_type = expr_type + PTR;
      elseif ~unit_was_array
          fail(sprintf('%d: bad address of', line));
      end                              % array name: address already in ax
      ```
- [ ] Tests (new corpus file `tests/programs/pp_addrof.c`):
      - positive: `int a[3]; int *p; p = &a[0]; *p = 42; return *p;` → exit 42
        (exercises the LC/LI drop path on an array element);
      - positive: `&a` on a bare array name → address usable, e.g.
        `int a[2]; int *p; p = &a; *p = 7; *(p+1) = 8; return *p*10 + *(p+1);`
        → 78 (exercises the array no-op path);
      - negative: `int main() { return &(1+2); }` → errors with
        `bad address of` (assert via try/catch + `strfind` on the message).
      - Check the existing `&` corpus (p3_pointer, p5_* etc.) still passes —
        all are lvalues and go through the drop branch.

### C3. fd registry leak (`sys_open` / `sys_close` / `sys_read`)

Append-only registry hits `fail('OPEN: too many open files (max 16)')` after 16
open/close cycles. Fix: mark freed slots and reuse.

- [ ] `sys_open`: before appending, scan `fidv` for a `-1` (freed) slot and
      reuse it; only append (with the 16 cap) when none is free.
- [ ] `sys_close`: after `fclose`, set `fidv(fd + 1) = -1` instead of leaving
      the slot.
- [ ] `sys_read` (and any other fd consumer): treat `fidv(fd + 1) < 0` as an
      invalid fd → return -1.
- [ ] Test (new corpus file `tests/programs/pp_fdreuse.c`): loop 20 times of
      `fd = open(p6_data.txt, 0); if (fd < 0) return 1; close(fd);` → exit 0.
      Fails today (17th open errors) and passes with the fix.

## Notes / decisions

- **No structural changes**: all fixes are targeted; no parser/VM redesign.
  The `&` flag approach was chosen over a last-instruction heuristic because
  `IMM` is shared by literals, strings, enums, and sizeof (ambiguous), while a
  unit-level flag is exact.
- **The clone quirk behind Phase B** (script local functions not resolvable by
  name in `-batch`) belongs in the gitignored runtime bug report — it is a
  runtime limitation, not a port bug.
- **Negative tests** (expected errors) use the existing `try/catch` +
  `strfind(e.message, ...)` pattern from run_tests group 2.
- **Reference parity**: none of the Phase C changes alter accepted-program
  semantics except the zero-divisor guard (previously silent 0) and the `&`
  error (previously silently accepted non-lvalues) — both edge cases the
  reference rejects/crashes on.
